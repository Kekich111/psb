# Юридический ассистент для юристов банка (ПСБ, Hack&Change 2026)

RAG-ассистент, который отвечает на вопросы по закрытой базе нормативных документов (законы + внутренние документы компании), **подтверждает каждый вывод ссылкой на пункт**, учитывает **редакцию на дату события** и **честно отказывается**, когда достоверный ответ по базе сформировать нельзя.

> Статус: проектирование завершено, реализация не начата. Этот README описывает **целевое** состояние. Разделы со статусом `planned` обновлять по мере готовности.
> Подробности: [ARCHITECTURE.md](ARCHITECTURE.md) · правила для ИИ-агентов и разработчиков: [AI.md](AI.md)

## Что внутри
- **Пайплайн из этапов**: анализ запроса → детерминированный поиск (с учётом редакций и контрагентов) → reason/compose в виде структурированных утверждений с ссылками → слой проверки достоверности → рендер ответа.
- **Один движок, два входа**: `solution.py` (пакетная автоматическая проверка на платформе) и веб-чат (финальный прототип с просмотром подтверждающих фрагментов) вызывают один и тот же `Assistant.answer(...)`.
- **Contract-first**: блоки общаются только через типы из `app/core/psb_contracts.py`.

## Как проверяется (кратко)
| Что | Как |
|---|---|
| Онлайн-этап | 70% LLM-судья (парное сравнение с baseline, 2 раунда) + 30% эксперты |
| Формула судьи | `Score = 0.7·MatchRate + 0.3·WinRate`; выдуманный факт = 0 за вопрос |
| Платформа | Docker, 8 CPU / 16 ГБ, **20 минут**, ZIP ≤ 128 МБ, **5 сабмитов в день** |
| Модели | DeepSeek V4.1 Flash (генерация), BAAI/bge-m3 (эмбеддинги), Qwen3 Reranker 8B (опционально), всё через прокси организаторов |
| Допуск к экспертам | балл судьи > 0, рабочий веб-интерфейс, полный комплект материалов |

## Быстрый старт `planned`

### Веб-чат (одна команда)
```bash
cp .env.example .env          # вписать ключи, если запускаете вне платформы
docker compose up --build     # UI: http://localhost:8080
```
Базу знаний положить в `data/knowledge-base.zip` (в репозиторий не коммитится).

### Пакетный прогон (как на платформе)
```bash
export DATA_DIR=data          # data/questions.csv + data/knowledge-base.zip
python solution.py            # создаёт submission.csv (id,answer)
```

### Оценка качества
```bash
make eval                     # парный локальный судья + детерминированные метрики
make check                    # линтер, типы, контрактные тесты, инварианты I1–I8
```

### Сборка ZIP для платформы
```bash
make submission               # -> dist/submission.zip
```
Скрипт `scripts/build_submission.py` кладёт в **корень** архива: `solution.py`, все `psb_*.py`, `requirements.txt`, при необходимости `emb_cache.npz`. Вложенных папок быть не должно.

## Переменные окружения
Платформа подставляет их сама; локально задаются в `.env`. **Значения ключей не коммитим и не логируем.**

| Переменная | Назначение | Примечание |
|---|---|---|
| `LLM_BASE_URL` / `OPENAI_BASE_URL` | адрес OpenAI-совместимого прокси | один прокси для генерации, эмбеддингов и rerank |
| `LLM_API_KEY` / `OPENAI_API_KEY` | служебный ключ | |
| `EMBEDDER_API_KEY`, `RERANKER_API_KEY` | отдельные ключи, если выданы | иначе берётся `LLM_API_KEY` |
| `LLM_MODEL` / `GEN_MODEL` / `OPENAI_MODEL` | модель генерации | **не хардкодить**, брать из env |
| `EMB_MODEL`, `RERANKER_MODEL` | эмбеддер и реранкер | |
| `TOP_K`, `RERANKER_TOP_N`, `CHUNKER` | параметры поиска с платформы | читаем, но не зависим от них |
| `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS` | параметры генерации и параллелизма | |
| `DATA_DIR` | каталог входных файлов | по умолчанию `data` |
| `VERIFY_MODE` | `full` / `lite` / `off` | наш: глубина проверки ответа |
| `DEADLINE_SEC` | мягкий дедлайн прогона | наш: по умолчанию 900 |
| `AS_OF_DATE` | «сегодня» для расчёта редакций | наш: по умолчанию текущая дата |
| `COMPANY_FULLCTX_TOKENS` | порог «все документы компании в контекст» | наш: по умолчанию 12000 |

Запросы: `POST {LLM_BASE_URL}/chat/completions`, `/embeddings`, `/rerank` с заголовком `Authorization: Bearer <ключ>`.

## Рабочий процесс команды
1. Контракт → фикстуры/фейки → контрактные тесты → реализация (см. [AI.md](AI.md)).
2. Перед PR: `make check` и `make eval` без регрессий.
3. Каждый платформенный сабмит записываем в `SUBMISSIONS.md` (дата, коммит, public-score, изменения). Лимит 5/день, тратим осознанно.
